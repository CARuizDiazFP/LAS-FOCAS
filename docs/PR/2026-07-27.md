# PR Diario — 2026-07-27

## Resumen de Cambios

Se refactorizó el módulo de administración `/admin/ingesta`, convirtiéndolo en un hub de navegación con dos sub-módulos: la ingesta existente de Servicios SLA (extraída a componente propio) y un nuevo flujo completo de ingesta masiva de cámaras con baneo administrativo desde un archivo Excel.

## Contexto y Alcance

- **Rama de trabajo**: `dev`
- **Módulos afectados**: `api/app/routes/ingest.py`, `core/services/`, `web/app/main.py`, `web/frontend/src/` (router, admin views, api client)
- **Objetivo**: Separar la ingesta SLA en su propia vista, agregar flujo de baneo masivo de cámaras vía Excel (`Camaras Criticas.xlsx`), y corregir la arquitectura de rutas del router admin unificado.
- **Restricción importante descubierta en sesión**: el archivo `web/frontend/src/admin/router/index.ts` **es código huérfano** y no está conectado a ningún entry point. El router real y activo del SPA admin es `web/frontend/src/router/index.ts` (router unificado). Ver sección de errores/aprendizajes.

## Errores y Bloqueos Post-Implementación

### Bug: `/admin/ingesta/camaras` redirigía a `/admin` en loop

**Síntoma**: Al hacer click en la tarjeta "Cámaras", el navegador iba a `/admin` y al reintentar quedaba en loop permanente.

**Causa raíz**: Se actualizó `web/frontend/src/admin/router/index.ts` creyendo que era el router activo del SPA admin. Este archivo **nunca es importado** por ningún entry point activo. El `src/admin/main.ts` existe pero tampoco está conectado al `index.html` de Vite (entry único: `src/main.ts`).

El SPA es **una sola aplicación Vue 3** con un único entry point (`src/main.ts`) que monta en `#app`, usando `src/router/index.ts` como router unificado. Las rutas admin viven como `children` anidadas bajo `{ path: '/admin', component: AppShell }`. Al no existir las rutas nuevas en ese router, el catch-all admin `':pathMatch(.*)*' → '/admin'` las capturaba, produciendo el loop.

**Solución**: Se agregaron los imports y rutas en `src/router/index.ts` (router activo).
