### `3897b16` — Fix CSS: centrar modales `<dialog>` rotos por reset global

**Archivos:** `web/frontend/src/panel.css`, `InfraTab.vue`

**Causa raíz:** `admin.css` (importado primero en `main.ts`) aplica `margin: 0` a todos los elementos via el reset universal `*, *::before, *::after { margin: 0 }`. Esto pisa el `margin: auto` del UA stylesheet que los navegadores usan para centrar `<dialog>` abiertos con `.showModal()` dentro del top-layer. Resultado: todos los modales se renderizaban pegados al margen superior-izquierdo.

**Fix en `panel.css`** (regla de tipo, especificidad 0-0-1):
```css
dialog {
  position: fixed;
  inset: 0;      /* ancla al viewport */
  margin: auto;  /* centra horizontal y vertical */
}
```

**Fix reforzado en `InfraTab.vue`** (estilos scoped, especificidad 0-1-0):
- `.camera-state-modal, .tracking-detail-modal` → `position: fixed; inset: 0; margin: auto`
- `.infra-generic-modal` → `position: fixed; inset: 0; margin: auto`
- Cubre: Cambio Estado, Detalle Tracking, Protocolo Protección, Resolver Conflicto, Baneos Activos, Dar Aviso, Limpiar Tracking.

`.tracking-detail-modal` en `panel.css` (definición duplicada) también corregida.
`.tracking-modal` (overlay full-screen con `margin:0` explícito) no se ve afectado.

### `ec7047d` — Fix reactividad: atajos de estado no disparaban búsqueda

**Archivos:** `InfraTab.vue`, `docs/web.md`

**Problema:** Al seleccionar un atajo de estado sin haber realizado una búsqueda previa, `camaras.value = []` y el computed `filteredCamaras` retornaba vacío. El botón "Buscar" permanecía deshabilitado porque `searchTerms.length === 0`.

**Cambios:**

```
Botón Buscar:
  Antes: :disabled="loading || searchTerms.length === 0"
  Ahora: :disabled="loading || (searchTerms.length === 0 && !activeStateFilter)"

toggleStateFilter():
  + Si !hasSearched, auto-dispara searchCamaras() (fetch all con terms:[])
  + Si hasSearched, el computed filtra sin llamada a la API

clearStateFilter() [función nueva]:
  + Con términos de texto: solo quita el filtro, grilla muestra todos los resultados
  + Sin términos de texto: resetea grilla al estado vacío inicial

searchCamaras():
  + Guard: permite ejecución si activeStateFilter está activo aunque terms=[]
  + Mensaje de status diferenciado según modo (texto vs. filtro de estado)
```

**Nota:** La API (`POST /api/infra/smart-search`) ya soportaba `terms: []` devolviendo todas las cámaras — no fue necesario ningún cambio de backend.

**Flujos cubiertos:**
1. Clic en atajo sin búsqueda previa → fetch all → filtra por estado inmediatamente
2. Clic en atajo con resultados cargados → filtrado instantáneo por computed
3. Clic `×` del chip con texto → solo quita filtro, grilla mantiene resultados de texto
4. Clic `×` del chip sin texto → grilla vuelve a vacío (estado inicial)
5. Botón "Limpiar" → `clearAll()` limpia todo (sin cambios en esa función)
