# PR Diario - 2026-08-19

## Resumen de Cambios

Cuatro features de Cromo Red, en la misma sesión, cada una construida con exploración + validación
de diseño antes de tocar código: (1) tabla de alias/exclusiones manuales para duplicados de Cromo
("escudo" consultado por la ingesta antes de persistir), (2) visor en vivo de un elemento Cromo
puntual desde el Verificador, (3) consolidación manual de grupos de Botellas duplicadas que hoy
quedaban sin resolver ("Revisión manual"), y (4) una herramienta nueva de Tool Kit, "Validar datos DB
Cromo", que aplica el mismo parseo de la ingesta a un `n_id` consultado en vivo, sin tocar la base de
datos local.

## Contexto y Alcance

- **Módulos afectados**: `core/services/cromo/` (paquete completo), `web/app/main.py` (endpoints
  nuevos), `web/frontend/src/api/cromo.ts`/`botellas.ts`, `AdminBotellasViewer.vue`,
  `VerificadorCromoView.vue`, nueva vista `ValidarDatosCromoView.vue`, router y `AppShell.vue`.
- **Objetivo 1 — escudo de ingesta**: Cromo tiene botellas duplicadas/triplicadas, muchas sin
  nombre, que la ingesta persistía tal cual. Se pidió una tabla de resoluciones manuales
  (`app.cromo_botella_alias`) consultada por la ingesta antes de guardar.
- **Objetivo 2 — visor en vivo**: auditar/resolver inconsistencias necesita ver qué dice Cromo AHORA
  para un `n_id`, sin esperar la próxima corrida de ingesta ni depender de lo ya guardado.
- **Objetivo 3 — consolidación de duplicados**: `AdminBotellasViewer.vue` (2026-08-14) sólo resolvía
  automáticamente 1 legado + 1 Cromo; todo lo demás (2+ Cromo, 2+ legado, mixtos) quedaba sin acción.
- **Objetivo 4 — Tool Kit "Validar datos DB Cromo"**: el pedido describía crear una vista
  "Verificador Cromo" — pero esa página ya existe. Se le presentó el solape al usuario, que confirmó
  una herramienta nueva y separada, 100% en vivo, sin tocar la base de datos local.

## Cambios Realizados

### 1. Escudo de alias/exclusiones (`cromo_botella_alias`)

- `db/models/cromo.py::CromoBotellaAlias` + migración `20260819_01_cromo_botella_alias.py`:
  `id_cromo_origen` (único, sin FK dura), `id_cromo_destino` (obligatorio sólo si
  `accion='fusionar'`), `accion` restringida por CHECK (no un enum de Postgres nuevo), `motivo`/
  `creado_por` (agregados más allá del mínimo pedido, únicos rastros de auditoría sin CRUD aún).
- `core/services/cromo/client.py::CromoClientError` ganó `status_code` (retrocompatible) para
  distinguir 404 real de cualquier otra falla.
- `core/services/cromo/alias_service.py` (nuevo): carga TODAS las filas en memoria una sola vez por
  corrida (nunca una query por objeto) y resuelve referencias — `'fusionar'` redirige al destino,
  `'ignorar'` anula la referencia a `NULL`.
- `core/services/cromo/ingesta.py` extendido: `_procesar_cable_directo`/`_procesar_botella_completa`/
  `_procesar_fusion_directa` consultan el alias antes de cada upsert; un `n_id` aliaseado nunca crea
  su propia `CromoBotella`.

### 2. Visor en vivo de un elemento Cromo

- `core/services/cromo/parser.py::ATRIBUTOS_CONOCIDOS` (centraliza números mágicos ya dispersos en
  `parse_botella`/`parse_cable`/`parse_fusion`).
- `core/services/cromo/live_lookup_service.py` (nuevo): `GET /db/objects/{id}` directo contra Cromo,
  nunca contra las tablas ya ingeridas.
- Endpoint `GET /api/infra/cromo/elementos/{n_id}/vivo` en `web/app/main.py` (deliberadamente en
  `web/app/`, no en `api/app/` — ver `docs/decisiones.md` para el porqué).
- `ModalVerificadorCromo.vue` (nuevo) — botón "Ver info en Cromo" en `VerificadorCromoView.vue`.

### 3. Consolidación manual de duplicados Cromo

- `core/services/cromo/verificador.py::tiene_cables_asociados_batch_sync` — señal "operativa"
  batcheada (una query para toda una página de grupos, nunca una por miembro).
- `core/services/cromo/consolidacion_service.py::consolidar_grupo_botellas` (nuevo) — grupo LIBRE de
  n_ids (no restringido a lo que el detector automático agrupó), reusa `apropiar_legado_a_cromo` tal
  cual para cualquier legado incluido, con guardas explícitas (destino ya marcado como basura,
  repunteo reportado no silencioso, recableo de cadenas de alias que quedarían rotas).
- 3 endpoints nuevos + enriquecido `.../viewer/duplicados` en `web/app/main.py`.
- `ModalConsolidarBotellas.vue` (nuevo) integrado en `AdminBotellasViewer.vue`.

### 4. "Validar datos DB Cromo" (Tool Kit)

- `core/services/cromo/validador_datos_service.py` (nuevo): reusa `parser.parse_objeto` (el
  dispatcher genérico por clase que también usa la ingesta) + `parse_arbol_botella`/
  `extraer_tubos_y_pelos` para armar el árbol completo (cables/tubos/pelos/fusiones). Cero acceso a
  la base de datos local — ni siquiera la etiqueta de clase sale de una tabla, sale del nombre del
  tipo Python devuelto.
- Endpoint `GET /api/infra/cromo/validar/{n_id}` (sin sesión de DB en absoluto).
- `ValidarDatosCromoView.vue` (nuevo) en `/toolkit/validar-datos-cromo`, nueva entrada en el dropdown
  Tool Kit de `AppShell.vue`.

## Impacto y Riesgos

- Ninguna de las 4 features toca datos ya ingeridos ni cambia comportamiento existente — todas son
  aditivas (tabla nueva, endpoints nuevos, una vista nueva, un enriquecimiento de campo opcional en
  un endpoint ya existente).
- El endpoint de consolidación SÍ puede mutar datos reales (alias + posible hard-delete de una
  Botella legado vía `apropiar_legado_a_cromo`) — gateado admin + CSRF, sin ejecución real contra
  datos de dev en esta sesión (sin credenciales de un usuario admin real a mano).
- Hallazgo real durante la verificación, no de esta feature: `tests/test_slack_cable_info.py`/
  `test_slack_ingreso_listener.py` hacen `os.environ.setdefault("TESTING", "true")` a nivel de
  módulo sin revertirlo — si corren antes en el mismo proceso de pytest, cualquier test posterior
  que dependa de CSRF real queda con el chequeo salteado en silencio. Sorteado con
  `monkeypatch.setenv("TESTING", "false")` explícito (mismo patrón que ya usaban otros tests para
  este caso); el origen del leak no se corrigió, fuera de alcance.
