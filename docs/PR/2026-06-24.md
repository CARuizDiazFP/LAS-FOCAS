# PR Diario - 2026-06-24

## Resumen de Cambios

Se implementó Docker Secrets para el stack de desarrollo `lasfocasdev`, reduciendo credenciales en texto plano y manteniendo compatibilidad temporal con variables de entorno. El alcance se mantuvo en rama `dev` y en `deploy/docker-compose.dev.yml`; no se modificó el compose productivo.

Además, se completó una segunda etapa de onboarding, CI y controles preventivos para que nuevos clones y pipelines puedan trabajar con `.secrets/` sin configuración manual insegura.

## Contexto y Alcance

- **Módulos afectados**: infraestructura dev, configuración Python compartida, acceso a PostgreSQL, bot Telegram, web, NLP, documentación y samples de entorno.
- **Objetivo**: leer secretos desde `/run/secrets/*` en contenedores dev y caer a variables tradicionales si el archivo no existe.
- **Restricción encontrada**: `git filter-repo` no está instalado en la VM, por lo que la purga de historial queda documentada como runbook pendiente.

## Cambios Realizados

- `.gitignore`: se agregó `.secrets/` para evitar versionar secretos locales.
- `.secrets/`: se creó localmente la estructura esperada para DB, web, Telegram, OpenAI, SMTP y Slack; los archivos quedan ignorados por Git.
- `deploy/docker-compose.dev.yml`: Postgres usa `POSTGRES_PASSWORD_FILE` y cada servicio dev monta solo los secretos que necesita.
- `core/config.py`: se agregó `get_secret(secret_name, env_var=None, default="")` con lectura desde Docker Secrets y fallback a `os.getenv`.
- `db/session.py`, `core/services/repetitividad.py`, `web/app/main.py`, `bot_telegram/*`, `nlp_intent/app/config.py` y `web/tools/reset_admin_password.py`: se adaptó la lectura de credenciales sensibles a Docker Secrets.
- `db/init.sql`: se eliminó el alta automática del usuario `admin` con hash bcrypt fijo.
- `scripts/start_dev.sh`: Alembic toma la contraseña desde `.secrets/db_password_v1.txt`, con fallback a `.env.dev`, y URL-encodea la clave para soportar caracteres especiales.
- `db/alembic/env.py`: se escaparon `%` en URLs inyectadas para compatibilidad con `configparser`.
- `deploy/env.sample`, `deploy/env.dev.sample`, `README.md`, `docs/api.md`, `docs/db.md`, `docs/entorno_dev.md` y `docs/infra.md`: se reemplazaron credenciales de ejemplo por placeholders y se documentó el flujo dev con Docker Secrets.
- `deploy/docker/bot.Dockerfile`: se copió `core/` para que el bot pueda reutilizar el helper compartido de secretos.
- `scripts/setup_local_secrets.sh`: bootstrap idempotente de `.secrets/*.txt` para desarrollo y CI.
- `scripts/check_no_plaintext_secrets.sh`: gate preventivo para bloquear `.env` versionados, llaves y passwords dev en texto plano.
- `.github/workflows/ci.yml`: se corrigió la estructura del workflow, se separó checkout/setup/install y se agregaron bootstrap de secretos y gate anti-secretos antes de pytest.
- `scripts/check_openai.py`: ahora lee `openai_api_key_v1` con el helper compartido y mantiene fallback a `OPENAI_API_KEY`.
- `.github/skills/secret-detection`, `sast-analysis` y `security-scan`: se actualizó el workflow de revisión para ejecutar el gate automático.
- `docs/Seguridad.md` y `docs/office_service.md`: se documentó la estrategia productiva con Docker Swarm/external secrets y se aclaró que `office_service` no consume secretos sensibles actualmente.

## Riesgos y Pendientes

- La purga de historial requiere instalar `git filter-repo`, ejecutar el runbook documentado en `docs/infra.md` con backup y coordinar `push --force-with-lease`.
- En entornos dev con volumen PostgreSQL ya inicializado, si cambia `.secrets/db_password_v1.txt` se debe actualizar el rol o recrear el volumen.
- La venv local no permitió completar todos los tests focalizados porque faltan dependencias (`apscheduler`, `asyncpg`, `orjson`); el stack Docker sí validó esas dependencias desde las imágenes.
- `tests/test_office_service_health.py` quedó no concluyente en la venv local porque no finalizó dentro de la ventana manual de validación.
- La estrategia productiva queda documentada, pero no implementada en `deploy/compose.yml` porque el alcance sigue siendo dev.
