# PR 2026-10-17 — Entorno agéntico: tokens, puertos por worktree, limpieza segura y auditor

## Resumen de cambios

- **Tokens / lazy loading:** `.gemini/rules/skill-*.md` pasa de copiar el cuerpo completo de las 25
  skills (264 160 bytes) a adaptadores de ≤ 15 líneas (25 545 bytes, **−90,3 %**) que preservan
  `triggers`/`globs` y apuntan a `.agentes-comunes/skills/<n>/SKILL.md`. Nuevo mirror nativo
  `.agents/skills/<n>/SKILL.md` (Agent Skills, frontmatter primero). `docs/superpowers/CATALOG.md`
  con una línea por skill de Superpowers y su precedencia frente a las locales.
- **Exclusión de indexado:** `.geminiignore` ampliado; nuevos `.copilotignore`, `.cursorignore` y
  `.aiderignore` con la misma matriz. `AGENTS.md` → "Contexto y tokens" (mapa primero, Acceso a Logs
  Bajo Demanda, Context-Splitting por dominio).
- **Mapa canónico:** `config/repository-map.json` + `scripts/generate_repository_map.py`
  (`--write`/`--check`, stdlib, metadatos `source_commit`/`generated_at_utc`/`manifest_sha256`,
  valida rutas y tope de 8 KiB) → `docs/REPOSITORY_MAP.md` (4,6 KB, 7 dominios).
- **Puertos y `.env.dev` por worktree:** columna `agentes.port_offset` (migración `ALTER TABLE`
  idempotente); `agent_worktree.py start --offset 1..90` (o el menor libre) con
  `puertos_agente(offset)` = api 8011, web 8090, vite 5173, office 8020, nlp_intent 8030 + offset.
  La asignación compara el conjunto de puertos de cada agente vivo (las bases se solapan:
  api 8011+10 == office 8020+1) y prueba `bind` en 127.0.0.1, antes de crear el worktree.
  `.env.dev` deja de ser symlink: copia privada 0600 con las variables del agente;
  `.agent-worktree.json` con agente/tarea/rama/offset/puertos.
- **`cleanup` seguro:** aborta (exit 1) si hay procesos con `cwd` dentro del worktree o archivos
  ignorados que no son runtime conocido (`.docx`, `.xlsx`, dumps…).
- **`cierre-sesion`:** únicos triggers directos `/cierre-sesion`, `Cerrar sesión`, `Cerremos sesión`;
  confirmación breve ante trabajo pendiente ambiguo; validación hacia `dev` sólo con pruebas focales;
  recursos Docker efímeros etiquetados `lasfocas.session=<agent-id>` y borrados por ID exacto.
  `pytest-focas` y `docker-cleanup` (retención prod `current` + 1 `rollback`) alineados.
- **Auditor:** `scripts/audit_agentic_environment.py` (archivos de gobernanza y exclusión, mapa
  vigente, frontmatter de skills, lista exacta de triggers de cierre, drift de mirrors, tope de
  adaptadores Gemini; leases/agentes vencidos como `warning:*` leyendo SQLite en sólo lectura).

## Impacto y riesgos

- **Transición de esquema (verificado sobre una copia de la base):** el código previo de
  `scripts/agentes/estado.py` construye `Agente(**fila)` y falla con `TypeError` en cuanto
  `agent_state.sqlite3` tiene `port_offset`. La migración corre al primer uso de la CLI nueva; todo
  worktree con código anterior debe hacer `sync` con `dev` antes de volver a usarla. Desde esta
  versión las filas se cargan ignorando columnas desconocidas.
- Los offsets aíslan procesos locales; el stack compose dev sigue siendo compartido
  (`name: lasfocasdev`, `container_name` y puertos fijos).
- `cleanup` ahora sale 1 cuando no remueve el worktree (antes 0 con una nota).
- Los procesos de otros usuarios o de contenedores no son visibles en `/proc` y no bloquean `cleanup`.

## Anexo — frontmatter primero en `.claude/skills/`

- **Problema:** los mirrors de Claude Code empezaban con el encabezado de 3 líneas, así que Claude
  Code no leía el frontmatter y mostraba "Nombre de archivo: SKILL.md" como descripción de las 25
  skills (sin activación por contexto).
- **Cambio:** `sync_skill_mirrors.py` emite el frontmatter primero también en `.claude/skills/`
  (como Codex y `.agents/`); los 25 mirrors regenerados, sólo reordenamiento. El auditor falla con
  `error:mirror_frontmatter_not_first:*` si un mirror de esas plataformas no empieza con `---`.
- **Verificación:** 121 passed en los 5 archivos de gobernanza; drift, mapa y auditor en exit 0.

## Anexo — `description` en los comandos slash

Los 11 archivos de `.claude/commands/` no tenían frontmatter y Claude Code mostraba
"Nombre de archivo: <comando>.md" como descripción. Se les agregó al principio `description` y
`argument-hint`; el auditor falla con `error:command_description_missing:*` si un comando no lo tiene.

## Anexo — Inconsistencias de Cromo: detector, cuarentena, viewer y avisos

Rama `feat/claude-inconsist3-inconsistencias-cromo-viewer`. Detalle funcional en `docs/infra.md`
("Inconsistencias de Cromo y cuarentena") y esquema en `docs/db.md`.

### Cambios

- **Fusiones de ODF 141** (`20261017_01`): el conector resuelve `conector -> 141 -> pelo` (o a otro
  conector) y guarda la 141 en `cromo_odf_conectores.fusion_odf_n_id`; el camino óptico usa la 141 del
  propio `/path`.
- **Detector** (`20261017_02`): casos `ISLA_FUSION`, `CABLE_SIN_EXTREMO` y `ELEMENTO_ISLA` en
  `app.cromo_inconsistencia` (+ pelos en uso). Isla pura confirmada en vivo = `AUTO` -> `CUARENTENA`;
  todo lo demás `MANUAL` -> `PENDIENTE` (falla cerrada). Cierre automático a `CORREGIDA` y reapertura.
  Corre al final de cada ingesta COMPLETA/SOLO_ODF/SOLO_PELOS_INNER OK y a mano.
- **Cuarentena** (`20261017_03`): vista `app.v_cromo_servicio_match_vigente`; todos los lectores del
  uso (verificador, traza, servicios sin ODF, detalle, inventarios, FO Monitor, camino óptico,
  auditoría de huérfanos) pasan de la tabla a la vista; los escritores siguen sobre la tabla. Test de
  guardia `tests/test_cromo_cuarentena_lectores.py`. Marcas: chip en el detalle web, "Info cable X BN"
  en Slack, `en_cuarentena` en API v1 `/pelos` (sale `ocupado`, `servicio_id: null`).
- **Viewer admin** `/admin/servicios/viewer/InconsistenciasCromo`, 7 endpoints bajo
  `/api/admin/infra/inconsistencias-cromo`, aviso en el panel Camino, exportación XLSX por localidad.
- **Avisos** (`20261017_04`): WebSocket admin siempre; Slack sólo con la fila `Cromo Inconsistencias`
  activa y con canales (nace inactiva). Guardas: primera detección sin adjunto; XLSX tope
  `CROMO_INCONSISTENCIAS_MAX_FILAS_AVISO` (500). `cromo_worker` suma `slack_sdk` y el secret
  `slack_bot_token_v1`.
- Variables nuevas: `CROMO_INCONSISTENCIAS_MAX_CONFIRMACIONES` (300),
  `CROMO_INCONSISTENCIAS_MAX_FILAS_AVISO` (500).
