# 2026-08-05 — Subred Docker /24, triage de tests y baja del admin mini-SPA

## Motivación

La red Docker dev (`lasfocas_dev_net`) no declaraba `ipam.config.subnet` y quedaba en el
`/16` por default de Docker (`172.19.0.0/16`). Ese bloque agregó una ruta conectada en el
host que secuestraba el tráfico hacia un destino real de la intranet, `172.19.217.20`,
dejándolo inalcanzable en vez de salir por `ens192`. Al resolverlo se detectó el mismo
riesgo latente en producción (`lasfocas_net`, `172.20.0.0/16`).

En paralelo, `pytest` traía una tanda de tests desalineados con el código vigente:
columnas de Excel renombradas, endpoints de auth migrados a JSON, y un mini-SPA de
administración que ya no se usa.

## Qué cambia

### Red Docker — subred `/24` explícita

- **Dev, aplicado**: `deploy/docker-compose.dev.yml` declara `ipam.config` con subred
  `172.19.0.0/24` (gateway `172.19.0.1`) en `lasfocas_dev_net`. Verificado que
  `172.19.217.20` vuelve a resolverse por la ruta por default del host tras recrear la
  red (`down` sin `-v` + `up -d`). Ningún servicio usa `ipv4_address`, así que no hubo
  IPs que reasignar.
- **Prod, solo en código**: `deploy/compose.yml` recibe el mismo tratamiento en
  `lasfocas_net` (`172.20.0.0/24`, gateway sin cambios). **No se ejecutó ningún comando
  contra el host de producción** — los 6 contenedores `lasfocas-*` siguen corriendo sin
  tocar, por directiva vigente de no intervenir prod sin aviso explícito puntual. El
  diff queda listo para mergear a `main` y aplicarse en la próxima ventana de
  mantenimiento.
- Procedimiento completo para la ventana de mantenimiento (pre-requisitos, comandos de
  baja/alta, verificación post-despliegue y rollback): nuevo doc
  [docs/mantenimiento_redes_produccion.md](../mantenimiento_redes_produccion.md).
- Detalle de causa raíz y alternativas descartadas: `docs/decisiones.md`, entradas
  2026-08-05 (dev y prod por separado).
- `docs/entorno_dev.md` documenta la subred dev en la sección "Red Docker"; las skills
  `docker-rebuild` (`.github/skills/`, replicada a `.gemini/rules/` y
  `.codex-skills/skills/`) y los agentes `docker` (`.github/agents/`, replicado a
  `.gemini/rules/`) suman la sección "Redes Docker (IPAM)" con la regla general: toda
  red nueva del repo debe declarar `ipam.config.subnet` explícito.

### Frontend — redirect de `/login` con sesión activa

`web/frontend/src/router/index.ts`: el guard ahora resuelve `/login` antes que la
excepción de rutas públicas. Si ya hay sesión autenticada y se navega a `/login`,
redirige a `/`; si no hay sesión, deja pasar como antes. Documentado en `docs/web.md`.

### Baja del mini-SPA admin muerto

Se eliminan `web/frontend/src/admin/App.vue`, `admin/components/AdminLayout.vue`,
`admin/main.ts` y `admin/router/index.ts` — montaban en `#admin-app`, un entry point
que ya no se sirve desde que las vistas admin se unificaron en `router/index.ts`. El
`window.CSRF_TOKEN` que seteaba `useSession` para compatibilidad con este código pasa a
documentarse como soporte de `chat/main.ts` (widget de chat embebible), que sigue
vigente. `docs/web.md` actualizado con el motivo de la baja.

### Fix de tipeo en aviso de Slack

`modules/slack_baneo_notifier/listener.py`: corrige "cotinuar"→"continuar" y
"aprobacion"→"aprobación" en los dos mensajes de cámara sin incidentes activos.
`tests/test_slack_ingreso_listener.py` actualizado para verificar el texto correcto.

### Triage de tests obsoletos (sin cambios de comportamiento)

Aplicando la heurística de `docs/pytest-focas` (lecciones 2026-07-30, ver
`[[feedback_test_failure_triage]]`), se revisó cada falla antes de tocar assert:

- **`tests/test_sla_legacy_report.py`**: los asserts todavía esperaban la columna
  `Horas Netas Reclamo` (columna U); el código (`core/sla/legacy_report.py`,
  `core/sla/parser.py`, `modules/informes_sla/*`) ya usa `Horas Netas Cierre Problema
  Reclamo` (columna P) desde un cambio de regla de negocio anterior no reflejado en
  estos tests. Se corrigieron nombres de test y valores esperados; no se tocó código de
  producción.
- **`tests/test_web_login.py`, `test_web_admin.py`, `test_web_baneos.py`,
  `test_web_infra_camera_state.py`, `test_web_repetitividad_flow.py`,
  `test_web_sla_flow.py`, `test_alarmas_ciena.py`, `test_vlan_comparator.py`**: seguían
  usando el flujo legacy (`POST /login` con form-data + scrapear `window.CSRF_TOKEN` del
  HTML de `/`). El login ya migró a `POST /api/auth/login` (JSON, devuelve `csrf` en el
  body) y la sesión se consulta con `GET /api/auth/session`, que reemplazó a
  `window.USER_ROLE` inyectado server-side. Se reemplaza el helper de login en cada
  archivo y se agregan `test_session_endpoint_devuelve_rol_autenticado` /
  `test_session_endpoint_sin_sesion` en `test_web_login.py`. Se elimina
  `test_panel_inyecta_user_role` (comportamiento migrado, ya no aplica) y se reemplazan
  los 4 tests de `/admin/usuarios` y `/admin/servicios` con gating server-side por dos
  tests parametrizados que verifican que el catch-all SPA sirve el shell sin importar
  sesión (el gating real es client-side + `_require_admin` por endpoint).
- **`tests/test_email_service.py`**: el `From` esperado no incluía el display name;
  `core/services/email_service.py` ya arma `From` con `formataddr((from_name,
  from_email))`. Se corrige el valor esperado y se decodifica el payload
  (`get_payload(decode=True)`) en vez de leerlo crudo, porque el cuerpo puede venir
  codificado (`quoted-printable`/`base64`).

## Fuera de alcance

No se aplicó el cambio de subred en el host de producción — queda pendiente de ventana
de mantenimiento, ver `docs/mantenimiento_redes_produccion.md`. No se tocó ningún
endpoint de `web/app/main.py`: los tests de auth solo se alinean con el contrato que ya
exponía la API.
