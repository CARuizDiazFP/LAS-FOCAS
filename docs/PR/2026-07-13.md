# PR Diario - 2026-07-13

## Resumen de Cambios

Se implementó la Fase 1 del módulo de Servicios con enfoque SPA desacoplada (Vue 3 + API REST), cubriendo ingesta de Excel/CSV, búsqueda operativa con scroll infinito, navegación a detalle histórico por ID origen y primera integración funcional de tarjetas en el dashboard de detalle.

Además, se dejó el entorno dev operativo con migración aplicada, smoke end-to-end validado (API y proxy web), y documentación técnica actualizada para reflejar el estado real del código.

## Contexto y Alcance

- **Módulos afectados**: `db`, `api`, `web` (backend same-origin), `web/frontend`, `core/parsers`, tests y documentación.
- **Entorno objetivo**: rama `dev` y stack de desarrollo Docker (`deploy/docker-compose.dev.yml` + `.env.dev`).
- **Objetivo funcional**: exponer catálogo de servicios SLA navegable, con enrutamiento histórico canónico y base de dashboard técnico para operación.

## Cambios Realizados

### Datos y DB

- `db/models/infra.py`
  - Extensión del modelo `Servicio` con campos SLA operativos:
    - `numero_primer_servicio`, `nombre_cliente`, `numero_linea`, `tipo_servicio`, `sla_prometido`, `direccion`, `localidad`, `provincia`, `direccion_2`, `estado_servicio`.
- `db/alembic/versions/20260713_01_servicios_sla_fase1.py`
  - Migración para agregar columnas/índices y backfill de `numero_primer_servicio`.

### Parser e ingesta

- `core/parsers/servicios_excel.py`
  - Parser robusto con normalización de encabezados (acentos/símbolos/alias) para Excel/CSV.
  - Ajuste para tratar valores vacíos y tokens `<NA>` como nulos reales.

### API core (FastAPI)

- `api/app/routes/servicios.py` (nuevo)
  - `POST /servicios/ingest` con upsert por `numero_primer_servicio` y resumen `inserted/updated/unchanged`.
  - `GET /servicios/search` con filtros multipropósito y paginación.
  - `GET /servicios/detail?id=...` para resolver ID consultado a **ID origen canónico** (`id_origen`).
- `api/app/main.py`
  - Inclusión del router de servicios.

### Web backend (proxy same-origin)

- `web/app/main.py`
  - `POST /api/servicios/ingest` (admin + CSRF) hacia API interna.
  - `GET /api/servicios/search` proxy autenticado.
  - `GET /api/servicios/detail` proxy autenticado para navegación histórica canónica.
  - `GET /api/infra/servicios/{servicio_id}/rutas`: búsqueda robustecida para aceptar `servicio_id`, `numero_primer_servicio` o `numero_linea`.
- `deploy/docker-compose.dev.yml`
  - Montaje de `api_key_v1` en `web` para habilitar autenticación hacia API interna.
