# PR Diario - 2026-08-20

## Resumen de Cambios

Borrado permanente admin-only de Cámaras/Botellas genuinamente vacías (basura heredada de backfills
viejos de Cromo Red — ej. Botella ID 9016313, nombre "0", sin cables, bajo una Cámara con un único
registro), con registro automático del `n_id` de Cromo eliminado en la tabla de exclusiones
(`app.cromo_botella_alias`, `accion='ignorar'`) para que la ingesta nunca la resucite.

## Contexto y Alcance

- **Módulos afectados**: `core/services/camara_botella_delete_service.py` (nuevo), `web/app/main.py`
  (2 endpoints nuevos), `web/frontend/src/api/botellas.ts`/`api/camaras.ts`,
  `CamaraDetailView.vue`, `VerificadorCromoView.vue`.
- **Objetivo**: el "Verificador Cromo"/"Validar datos DB Cromo" (2026-08-19) dejaron a la vista esta
  basura sin ninguna forma de limpiarla desde el frontend.
- **Confirmado explícitamente por el usuario (2 preguntas de alcance) antes de diseñar**:
  1. **Bloquear, nunca forzar** — si el elemento (o cualquier hijo, para una Cámara) tiene
     Cables/Empalmes/Ingresos/Fusiones reales asociados, se rechaza sin borrar nada.
  2. **Todo o nada** en `eliminar_camara` — un solo hijo bloqueado aborta la operación completa.

## Cambios Realizados

- `core/services/camara_botella_delete_service.py` (nuevo): `eliminar_botella(origen, id, usuario)` +
  `eliminar_camara(camara_id, usuario)`, compartiendo los mismos helpers de chequeo
  (`_bloqueo_camara`/`_bloqueo_cromo_botella`) para no divergir con el tiempo. `eliminar_botella` reusa
  literalmente `eliminar_camara` para el paso "¿el padre quedó vacío?", heredando gratis el mismo
  fail-safe contra los 6 casos reales que violan el invariante de 2 niveles Cámara→Botella. Cada
  `CromoBotella` eliminada registra su `n_id` en `app.cromo_botella_alias` (upsert-por-origen, mismo
  patrón que `consolidacion_service.py`).
- Endpoints nuevos en `web/app/main.py` (admin, CSRF): `POST /api/infra/botellas/eliminar`,
  `POST /api/infra/camaras/eliminar` — 400 con `{error, bloqueos}` si rechaza.
- Frontend: botón "Eliminar Botella"/"Eliminar Cámara" gateado por `isAdmin` (`useSession`) con
  confirmación inline estilo `AdminBaneos.vue` (no modal), en `CamaraDetailView.vue` (redirige a
  `/infra` al confirmar — la vista deja de tener sentido) y `VerificadorCromoView.vue` (limpia el
  resultado local + mensaje transitorio de éxito).
- `tests/test_camara_botella_delete_service.py` (nuevo, 22 tests) + 3 tests de ruta en
  `tests/test_web_botellas_admin.py`.
- `docs/infra.md` (nueva sección narrativa + 2 entradas de endpoint) y `docs/decisiones.md` (nueva
  entrada fechada) actualizados.

## Criterios de Aceptación

- [x] Borrar una Botella evalúa si la Cámara padre queda vacía y, de ser así, la elimina también.
- [x] Borrar una Cámara elimina sus Botellas asociadas (todo o nada si algún hijo bloquea).
- [x] Los `n_id` de Cromo eliminados quedan registrados automáticamente para ser ignorados en
      futuras ingestas.
- [x] Los botones de eliminación están ocultos para cualquier rol que no sea admin.
- [x] Documentación actualizada (`docs/infra.md`, `docs/decisiones.md`).

## Impacto y Riesgos

- Operación destructiva real (hard delete), mitigada por: gateo admin+CSRF, política bloquear-nunca-
  forzar verificada contra Cable/Empalme/Ingreso/CromoCable/CromoFusion/alias-destino, y todo-o-nada
  en el cascada de Cámara.
- Sin sobreviviente (a diferencia de `unificar_camaras`/`apropiar_legado_a_cromo`), así que
  `CamaraEstadoAuditoria` cascadea junto con la fila borrada — no queda auditoría persistente en base
  de datos, sólo el `logger.info(...)` del endpoint. Deliberado, fuera de alcance de este ticket.
- Bugs reales encontrados y corregidos ANTES de implementar, por un agente de planificación: (1)
  confusión inicial entre `Cable` (legado) y `CromoCable` (Cromo) para el chequeo de bloqueo de una
  `CromoBotella`; (2) trampa de `autoflush=False` — sin `session.flush()` explícito entre borrar el
  hijo y chequear si el padre quedó vacío, la comprobación seguiría viendo la fila recién borrada.
- Sin borrado real contra datos de dev en esta sesión (sin credenciales de un usuario admin real a
  mano) — el comportamiento completo está cubierto por los 22 tests de servicio con mocks.
