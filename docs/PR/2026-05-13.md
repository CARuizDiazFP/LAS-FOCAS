# PR 2026-05-13: Refactor de Cámaras FO en Vue 3

## Resumen

Se refactorizó la gestión visual de cámaras en Infraestructura FO para separar la consulta rápida del detalle operativo. La grilla principal quedó resumida y se creó una vista dedicada por cámara con carga paralela y modales aislados por dominio.

## Cambios realizados

### Frontend SPA
- `InfraTab.vue` ahora muestra únicamente nombre canónico, ID numérico y estado por color en cada tarjeta.
- El CTA de cada tarjeta pasó de `Editar estado` a `Detalle`.
- Se agregó la ruta SPA `/infra/Camaras/:id` en `web/frontend/src/router/index.ts`.
- Se creó `CamaraDetailView.vue` con header destacado, botón `Editar estado` para admin y dashboard de tarjetas.
- Se desacopló el modal de edición de estado a `CamaraEstadoModal.vue`.
- Se agregaron modales aislados `ModalAlias.vue`, `ModalServicios.vue` y `ModalRegistros.vue`.
- Se creó `AccordionItem.vue` como acordeón reutilizable con transición dinámica de altura para `ModalRegistros.vue` y futuras superficies del frontend.
- `ModalServicios.vue` ahora lista solo IDs de servicio ordenados de mayor a menor y abre `TrackingDetail.vue` en un segundo `dialog` modal real por servicio, corrigiendo el apilado visual por delante del modal padre.
- `ModalRegistros.vue` quedó dividido en tabs `Ingresos/Baneos`; los baneos ordenan por fecha, arrancan cerrados y usan accordions con transición suave.
- La pestaña `Ingresos` de `ModalRegistros.vue` queda preparada sobre un arreglo reactivo vacío y reserva el campo `Técnico solicitante` para la futura hidratación.
- `CamaraEstadoModal.vue` recupera el estilo dark coherente con el dashboard del panel.
- `PanelView.vue` sincroniza el tab activo con `?tab=infra` para mantener el contexto al volver desde el detalle.

### Backend same-origin (`web`)
- Se agregó `GET /api/infra/camaras/{id}` para el resumen operativo base de una cámara.
- Se agregó `GET /api/infra/camaras/{id}/aliases` para alias conocidos desde `app.camara_alias`.
- Se agregó `GET /api/infra/camaras/{id}/registros` para auditoría manual y baneos relacionados.
- Se reutilizó la serialización existente de cámaras y el servicio `core/services/camara_estado_service.py`.
- Se mantuvo `GET/POST /api/infra/camaras/{id}/estado` como flujo admin-only con CSRF.

### Pruebas
- Se amplió `tests/test_web_infra_camera_state.py` para blindar:
  - presencia de `id` en la serialización web
  - detalle base por cámara
  - alias conocidos
  - registros parciales de auditoría y baneos

### Documentación y operación
- Se actualizaron `docs/web.md`, `docs/infra.md` y este PR diario para reflejar el comportamiento final de `ModalServicios.vue`, `ModalRegistros.vue` y `CamaraDetailView.vue`.
- Se corrigieron hosts y URLs activas en `docs/api.md`, `docs/Guia_de_Uso.md`, `docs/informes/alarmas_ciena.md` y `docs/informes/sla.md` para distinguir mejor producción (`172.18.208.162:8080`) de desarrollo (`localhost:8090`).
- Se sincronizó el bloque de estructura del repo en `README.md` con las carpetas reales actuales.
