### Errores y bloqueos
- Intento inicial de arranque con `./Start --no-down`: causa confirmada - ese script usa `deploy/compose.yml`, el stack `lasfocas`, y el worktree no tiene el directorio local `.secrets/` requerido por sus mounts. El arranque falló antes de crear o recrear contenedores.
- Validación autenticada E2E: causa no confirmada - el flujo de alta de usuario QA temporal no se ejecutó; el entorno quedó limpio. Impacto: falta evidencia HTTP final de `OK` y de `SIN_SEMILLA` bajo sesión admin real.

### Soluciones aplicadas
- Validación de runtime: se operó sólo mediante `deploy/docker-compose.dev.yml` y `.env.dev` del checkout raíz, reconstruyendo `lasfocasdev-web`. Regresión futura: no invocar `./Start` para desarrollo, pues selecciona el stack base.
- Aislamiento operativo: el usuario indicó explícitamente que los contenedores `lasfocas` de producción nunca se tocan; se inspeccionaron ambos proyectos y no se crearon contenedores ajenos. Toda modificación o validación posterior debe dirigirse exclusivamente a `lasfocasdev`.
