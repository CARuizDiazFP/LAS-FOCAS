### Errores/bloqueos reales enfrentados y solución aplicada

1. **API key equivocada en la verificación E2E contra `lasfocasdev-api`.** Síntoma: `403 Credenciales
   inválidas` usando `Authorization: Bearer $(cat .secrets/api_key_v1.txt)` contra
   `http://localhost:8011`. Causa raíz confirmada: ese archivo es el secreto de **prod**; el
   contenedor dev monta `.secrets/Dev_api_key_v1.txt` (mismo patrón `Dev_`-prefix ya conocido para la
   password de Postgres). Solución: `docker exec lasfocasdev-api cat /run/secrets/api_key_v1`
   comparado contra los archivos host hasta encontrar la coincidencia. Condición de regresión:
   ninguna nueva — patrón ya existía, sólo faltaba generalizado a `api_key_v1` en la skill (ver
   mejoras de aceleración abajo, ya aplicada).
2. **`docker compose up -d web` marcó `lasfocasdev-postgres` como `Recreate`/`Recreated`** en el
   primer rebuild puntual (antes del recreate completo del stack), pese a incluir `--env-file
   .env.dev`. No se investigó la causa raíz (podría ser drift de red u otra causa de Compose) porque
   no bloqueó el trabajo — se verificó integridad de datos (`count(*)` de `app.servicios` + la fila
   específica del ejemplo del usuario) antes y después, sin pérdida. **Sin resolver**: si se repite en
   una próxima sesión, vale la pena diagnosticar con el mismo procedimiento de "drift de red" que ya
   documenta la skill `docker-rebuild` para el caso de `up` incremental.

### Mejoras agénticas aplicadas en este cierre

- **Aceleración (skill `docker-rebuild`, ya aplicada)**: agregada la sección "Curl real de
  verificación E2E contra `lasfocasdev-api`: usar la API key de DEV, no la de prod" — mismo patrón
  `Dev_`-prefix que la skill ya documentaba para `db_password_v1`, ahora explícito también para
  `api_key_v1`. Evidencia: obstáculo real de esta sesión (#1 arriba). Beneficio: evita repetir el
  mismo diagnóstico (`403` silencioso sin pista de la causa) en la próxima verificación E2E real
  contra `lasfocasdev-api`. Costo de mantenimiento: bajo (una sección corta, mismo patrón que la ya
  existente). Replicada en los 5 mirrors requeridos para que sea invocable/consultable desde
  cualquiera de los entornos agénticos del proyecto.

### Mejoras agénticas evaluadas y descartadas (sin evidencia suficiente todavía)

- **Prevención sobre el "Recreate" inesperado de `postgres`** (bloqueo #2): con un solo caso
  observado y sin causa raíz confirmada, no amerita todavía una sección nueva de skill — sólo una
  nota en este cierre. Si se repite en otra sesión, ahí sí hay evidencia suficiente para documentar un
  procedimiento de diagnóstico concreto.

  adicional.
